# review-writer 当前项目规格

版本：M0/PR A
定位：最小、案例中立、离线优先的本地项目契约
当前成熟度：可用于项目输入和证据边界校验，不是完整综述生成器

## 1. 面向用户的目标

用户把一组已经准备好的化学论文和 SI 放入本地项目后，系统先回答四个问题：

1. 我到底指定了哪些文件？
2. 这些文件是否真的在项目范围内，是否被替换过？
3. 这个项目的目标和范围是什么？
4. 如果配置变化，哪些后续结果不能继续直接使用？

当前版本把这四个问题做成确定性本地检查。它不把“能运行脚本”包装成“已经
完成科学综述”。

## 2. 用户可见能力

| 能力 | 用户得到的变化 | 当前使用方式 | 明确限制 |
| --- | --- | --- | --- |
| 项目初始化 | 不必手写完整目录，能得到统一项目骨架 | scripts/project.py init | 需要用户显式提供每个来源绑定 |
| manifest 校验 | 目标、范围、语料政策和路径规则一致 | scripts/project.py validate | 只校验结构和文件字节，不判断科学内容 |
| 来源哈希 | 可以发现来源文件被替换或内容漂移 | 初始化和验证时自动计算 | SHA-256 只证明字节一致，不证明论文结论正确 |
| 路径安全 | 防止绝对路径、越界路径和符号链接绕过边界 | 初始化/验证自动执行 | 不替用户管理外部文件备份 |
| 快照状态 | 能发现当前配置是否影响已有不可变结果 | scripts/project.py status | 需要后续工作流提供完整封闭快照 |
| 旧案例适配 | 旧案例可通过封闭 adapter 只读接入 | 由内部 M0 测试覆盖 | 不把旧案例字段变成公共产品字段 |

## 3. 输入规格

project.manifest.json 是用户可编辑文件，但只允许以下边界：

- manifest_schema_version 固定为 project-manifest-1.0；
- project_id、项目标题、用户目标和范围；
- discovery_policy=CLOSED_CORPUS；
- network_policy=OFFLINE_ONLY；
- 输出文稿语言约束为 en，引用风格为 BRACKETED_NUMERIC；
- seed_source_root、project_data_root、export_root 三个相对目录；
- 每个来源的唯一 ID、论文 ID、相对路径、MAIN|SI 文档角色和使用角色；
- 可选的封闭 adapter ID，不能填写动态模块、命令、URL 或 provider。

结构由 ProjectManifest JSON Schema 约束，文件系统边界由运行时检查补足。每篇
论文必须恰好一份 MAIN；SI 必须属于同一篇论文。

## 4. 核心不变量

### 4.1 输入不越界

来源必须是项目语料根目录内的普通文件。绝对路径、父目录逃逸、反斜杠、重复
分隔符、符号链接和跨平台规范化后的路径冲突都会被拒绝。

### 4.2 证据不伪造

M0 会记录来源内容哈希，并要求后续证据引用绑定当前来源和解析版本。哈希、
候选结果、自动抽取和历史报告都不能直接成为研究者确认。

### 4.3 历史结果不被配置覆盖

用户可以编辑当前 manifest，但下游不可变记录必须绑定规范化配置哈希。配置
改变时，status 返回 CONFIG_CHANGED 和静态受影响阶段：

```text
CORPUS → CLAIMS → CHECKPOINT → DRAFT → RUN → RELEASE
```

这不是完整的依赖图传播器，而是当前最小版本提供的安全提示。

### 4.4 冲突和不确定性保持可见

来源内部冲突、跨来源分歧、学术争议和文件/解析错误不是同一类问题。M0 的
确定性规则会拒绝把不可比数据或 artifact 错误包装成学术争议。

## 5. 输出和状态

初始化输出：

- project.manifest.json：用户可以编辑的项目配置；
- inputs/papers/：用户准备的输入文件；
- outputs/project-state/：后续不可变项目状态的预留目录；
- exports/：后续导出的预留目录；
- 命令报告中的 source_hashes 和 resolved_config_sha256。

验证状态：

- VALID：当前 manifest 和来源满足 M0 输入边界；
- CONFIG_CURRENT：当前配置与已有封闭快照一致；
- CONFIG_CHANGED：当前配置已变化，需要按报告重新检查受影响阶段；
- INVALID：输入不满足规格，命令返回码为 2。

VALID 或 CONFIG_CURRENT 不是科学发布许可，也不代表有领域专家签字。

## 6. 明确排除

为了保持可理解性和可恢复性，当前主线不包含：

- 开放式文献发现、Provider、RAG 或网络请求；
- PDF/MinerU/Chemical Parse 的真实科学处理；
- 自动 claim 注册、自动冲突判断或自动机制确认；
- 自动生成正文、图表、DOCX/PDF；
- Dashboard、多用户、数据库、部署、后台调度和在线迁移；
- 以单个旧案例的论文 ID、计数或化学术语硬编码公共产品。

这些能力不是“被验证后默认开启”，而是需要新的范围决定、新鲜输入和独立验收。

## 7. 进入下一阶段的条件

只有当真实用户使用 M0 后仍有明确阻塞，下一阶段才考虑增加能力。候选需求
必须同时说明：用户遇到的具体问题、完成后减少的操作或增加的可信度、输入/输出
边界、失败时如何恢复，以及对应的新鲜离线验收证据。

不能改善用户结果、理解或可恢复性的模块继续停车或删除。历史分支、worktree、
外部 PDF/SI 和项目输出保留与否，按收敛清单的可恢复性规则处理，不以“分支多”
作为产品功能。
